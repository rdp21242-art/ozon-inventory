# Мой склад — Ozon Seller API

Обновлённая версия складского счётчика: GitHub Pages (интерфейс и OCR) + отдельный Cloudflare Worker (защищённый серверный прокси к Ozon Seller API).

## Что умеет версия

- Загружает каталог товаров непосредственно из Ozon Seller API.
- Получает список FBS-складов и текущие остатки/резервы.
- Ищет товар по `offer_id` — артикулу продавца на этикетке.
- Распознаёт артикул камерой телефона через OCR; есть ручной поиск.
- Каждое нажатие `+1` увеличивает фактический пересчёт с нуля.
- До отправки показывает все непросканированные товары. По умолчанию они отмечены для установки в 0; можно снять отметку, чтобы не менять конкретный товар.
- Перед записью Worker заново запрашивает резервы и вычитает их из физического пересчёта, чтобы не прибавлять зарезервированные единицы повторно.
- Отправляет остатки в Ozon только после явного подтверждения.
- Показывает результаты и ошибки по каждому товару.
- Сохраняет прогресс в браузере и позволяет скачать/восстановить резервную копию.

## Важно о резервах Ozon

Для FBS Ozon учитывает зарезервированные единицы отдельно. В API обновления `stock` передаётся доступное количество, а резерв прибавляется Ozon отдельно. Поэтому перед отправкой Worker получает актуальный `reserved` и отправляет `max(0, физический_пересчёт - reserved)`. Если резерв больше физического количества, отправится 0 доступного остатка; резервированные единицы останутся зарезервированными — API не снимает резерв этим методом. Проверь такие предупреждения в результате.

## Часть A. Публикация сайта на GitHub Pages

1. Скачай и распакуй архив.
2. Открой свой существующий репозиторий `ozon-inventory` на GitHub.
3. Замени в корне репозитория файл `index.html` новым файлом из архива. Старый `README.md` можно заменить новым.
4. `worker.js` можно также сохранить в репозитории как исходник, но GitHub Pages его не запускает.
5. Нажми `Commit changes` и дождись публикации GitHub Pages.
6. Адрес сайта остаётся прежним: `https://rdp21242-art.github.io/ozon-inventory/`.

## Часть B. Создание отдельного Cloudflare Worker

Не заменяй Worker планировщика `moiritm-sync`: для склада создаём отдельный Worker.

1. Открой https://dash.cloudflare.com/ и войди в аккаунт.
2. Открой **Workers & Pages** → **Create** → **Create Worker**.
3. Назови Worker `ozon-inventory-api` и создай его.
4. Открой **Edit code**.
5. Полностью замени код редактора содержимым файла `worker.js` из архива.
6. Нажми **Deploy**.
7. Скопируй адрес Worker вида `https://ozon-inventory-api.<твой-поддомен>.workers.dev`.

## Часть C. Добавление переменных и секретов Worker

В настройках созданного Worker открой **Settings** → **Variables and Secrets** (название раздела может немного отличаться). Добавь:

| Имя | Тип | Значение |
|---|---|---|
| `OZON_CLIENT_ID` | Secret | Client-Id из кабинета Ozon |
| `OZON_API_KEY` | Secret | API-ключ Ozon |
| `APP_TOKEN` | Secret | Придумай длинный случайный пароль для доступа к приложению |
| `APP_ORIGIN` | Text / Variable | `https://rdp21242-art.github.io` |

Секреты `OZON_CLIENT_ID`, `OZON_API_KEY` и `APP_TOKEN` нужно именно добавить как **Secret**, не как обычный текст. После добавления переменных нажми **Deploy** / **Save and deploy**, если Cloudflare попросит.

**Не вставляй Client-Id и Api-Key в GitHub, HTML-файл или в переписку.** Они должны оставаться только в секретах Worker.

### Права API-ключа Ozon

Ключ должен иметь доступ к чтению товаров/складов/остатков и записи остатков. Для метода `/v2/products/stocks` нужен ключ с правами записи остатков (обычно роль Admin). Ключ только для чтения не сможет отправить остатки. Если Ozon вернёт `Invalid Api-Key` или `Access denied`, проверь тип и права ключа.

1. Открой `https://rdp21242-art.github.io/ozon-inventory/`.
2. В блоке «Подключение» вставь адрес Worker из части B.

## Рабочий процесс

1. Нажми «Загрузить товары из Ozon» — это обновит каталог и исходные остатки.
2. Включи камеру и сканируй этикетки с артикулом. Программа ищет совпадение по `offer_id`.
3. Убедись, что найден правильный товар, и нажми `+1`.
4. Повторяй до окончания физического пересчёта.
5. Нажми «Проверить остатки». В списке будут товары, которые не встретились при сканировании.
6. По умолчанию все непросканированные товары отмечены для отправки с количеством 0. Сними галочку у тех, которые нужно оставить без изменений.
7. Проверь сводку и нажми «Отправить подтверждённые остатки в Ozon».
8. Дождись ответа. Если есть ошибки, исправь их и проверь историю остатков в кабинете Ozon.

## Ограничения и меры предосторожности

- В этой версии нет автоматической записи после каждого сканирования. До подтверждения все количества хранятся только в браузере.
- Обновление остатков — реальное действие в кабинете Ozon. Откатить его автоматически нельзя.
- Перед отправкой убедись, что каталог загружен с правильного склада и пересчёт завершён.
- Если товар не сканировали и его отметка включена, ему будет отправлен 0. Если отметку снять, этот товар не будет изменён.
- Резервированные заказы нельзя обнулить этим методом. Worker вычитает резерв из физического количества и показывает предупреждение, если резерв больше пересчёта.
- Прогресс хранится в браузере конкретного устройства. Для переноса скачай резервную копию.
- Камера доступна только на HTTPS. OCR-библиотека загружается с CDN и требует интернет.
- API каталога может содержать товары разных состояний. Перед первым реальным обновлением проверь список товаров и склад. Не отправляй остатки, пока не убедишься, что каталог соответствует нужному ассортименту.

## Используемые методы Seller API

- `POST /v3/product/list` — список товаров с пагинацией.
- `POST /v3/product/info/list` — названия и сведения о товарах.
- `POST /v2/warehouse/list` — список складов.
- `POST /v2/product/info/stocks-by-warehouse/fbs` — остатки FBS и резервы.
- `POST /v2/products/stocks` — запись остатков.

Справка Ozon: https://dev.ozon.ru/ и https://docs.ozon.ru/api/seller/
